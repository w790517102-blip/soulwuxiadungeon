# 《語破江湖》存讀檔系統｜第一階段現況報告

> 性質：只讀調查，沒有修改任何程式、場景或存檔，沒有 commit。
> 範圍：主選單讀取、遊戲內儲存、遊戲內讀取、SaveManager 與存檔資料。
> 截圖：`system_menu_save_tab_real_screenshot.png` 是**真實畫面**（用既有三份存檔唯讀開啟系統選單「系統」分頁擷取）。下方 ASCII 圖則是依程式推導的示意。

---

## 1. UI 現況

### A. 主選單 → 讀取進度
- 按鈕：有，在 `scenes/main.tscn` 叫 `LoadButton`。
- 接線：目前只接到 `main.gd` 的 `_on_placeholder_pressed`，畫面上顯示「尚未開放」。
- 讀取畫面：**沒有**，只是預留。
- 能否讀既有三個存檔：**目前不能**（原因見第 5 節）。

### B / C. 遊戲內 → 系統 → 儲存進度／讀取進度
**存檔與讀檔是同一個畫面，沒有分開。** 位置：`scenes/system_menu.tscn` 的「系統」分頁，元件 `SavePopup`（腳本 `scripts/SavePopup.gd`）。

示意圖（真實截圖見同資料夾 png）：

```
┌────────────────────────────────────────────────────────────┐
│[狀態][道具][裝備][武術][隊伍][見聞][任務][系統]              │
│ ┌縮圖┐ 壹 [ 選取 ]  存檔 1｜2026-10-12 14:38:45｜飲月山莊內     │
│ └────┘              主線：main_001｜第10步｜尋找飲月山莊的左飲   │
│ ┌縮圖┐ 貳 [ 選取 ]  存檔 2｜…                                   │
│ ┌縮圖┐ 參 [ 選取 ]  存檔 3｜…                                   │
│ [存檔] [讀取]                                  [回標題畫面]      │
└────────────────────────────────────────────────────────────┘
```

**操作流程**
1. 按某格「選取」→ 記下欄位編號。
2. 按「存檔」→ 直接覆寫該格，並重新整理三格文字。
3. 按「讀取」→ 直接讀檔。選到空格時「讀取」為灰色；初始也是灰色。

**每格實際顯示**：縮圖、壹／貳／參、選取鈕、存檔編號、日期時間、地圖名稱、主線（`main_001｜第N步｜說明`）。

**逐點回答**
| 問題 | 現況 |
|---|---|
| 三個欄位如何建立 | 場景裡手寫三個 `SaveSlot` 節點（含壹貳參文字），`SavePopup.gd` 用寫死的三節點陣列 |
| 空格與已有存檔如何區分 | 空格顯示「存檔 N｜尚無資料」；格式壞掉顯示「異常格式」，且被當成空格（可被覆寫） |
| 覆蓋存檔有確認嗎 | **沒有**，直接覆寫，也沒有成功提示 |
| 讀檔是否提示未儲存進度會遺失 | **沒有**，直接讀 |
| 選取狀態 | `SaveSlotUI.mark_selected()`（顯示「✔ 選取中」）寫了但從未被呼叫，畫面看不出選了哪格 |
| 「回標題畫面」 | **沒有接任何函式**，按了沒反應 |
| 讀檔後 | `SaveManager` 關閉系統選單並解除暫停 |
| 何時不能開系統選單 | 讀檔中、角色不能動（劇情中）時，`SystemMenuControl._can_open_menu_now()` 會擋住，所以劇情中不能存檔 |

## 2. 程式架構

```
SystemMenu (autoload, SystemMenuControl.gd)    ESC 開／關；開之前先快取畫面縮圖
 └ system_menu.tscn (system_menu.gd，3369 行，管理所有分頁)
    └ VBoxContainer/系統
       └ SavePopup (SavePopup.gd)               選取記憶、存檔鈕、讀取鈕
          ├ VBoxContainer/SaveSlot1..3 (SaveSlotUI.gd)
          │    縮圖、壹貳參 Label、SelectButton、資訊 Label
          └ SaveButton / LoadButton / MenuButton(未接線)
SaveManager (autoload)                           存／讀／摘要，所有邏輯都在這
```

| 按鈕 | 腳本與函式 |
|---|---|
| 選取 | `SaveSlotUI._on_select_button_pressed` → 發出 `slot_selected` → `SavePopup._on_slot_selected` |
| 存檔 | `SavePopup._on_save_button_pressed` → `SaveManager.save_to_slot(i)` |
| 讀取 | `SavePopup._on_load_button_pressed` → `SaveManager.load_from_slot(i)` |
| 回標題畫面 | 無 |

另：`scripts/SaveLoadExample.gd` 是舊範例，呼叫不存在的 `SaveManager.save_game`，也沒有任何場景引用，屬廢程式。

## 3. 存檔資料（針對十個問題）

1. **最多幾格**：3 格。
2. **數量限制寫在哪**：至少 4 處：`SLOT_COUNT = 3`、`_valid_slot()`、`SavePopup.gd` 手寫三節點陣列、場景內三個 `SaveSlot` 節點（壹貳參文字寫死）。
3. **檔名與路徑**：
   - 存檔 `user://save/slot_%02d.save`
   - 備份 `slot_%02d.bak`、暫存 `slot_%02d.tmp`
   - 縮圖 `thumb_slot_%02d.png`
   - `%02d` 為兩位數，99 格以內路徑規則不需改。
4. **是否有獨立摘要 Metadata**：沒有。摘要是臨時整份讀檔後取欄位（`get_slot_summary`）。
5. **是否記錄等級／場景名／遊玩時間／日期**：
   - 有：時間戳、地圖顯示名稱、縮圖路徑、主線 id／步驟／說明。
   - 沒有：角色等級（隊伍資料內有，但摘要沒取）、遊玩時間。
6. **正式主線章節編號**：**沒有**。主線只有 `id = main_001`、階段數字 `stage`（1~11）和中文 `chapter_title`（「靜默的琴聲」），來源是 `QuestManager.gd` 的 `MAIN_QUEST_DEFS`，其中沒有章節編號。畫面上的「main_001」是直接顯示 id。要做「第 X 章」，需在 `MAIN_QUEST_DEFS` 新增章節欄位；不應由場景推測，也不應直接拿 stage 當章節。
7. **場景截圖／縮圖**：有。存檔時另存高 140px 的 PNG，內容是「打開系統選單那一刻」的畫面。
8. **讀清單是否完整解析**：是。每格開檔並整份解碼（現有存檔約 7~18 KB）；存檔後三格全部重刷。
9. **存讀是否同源**：同一份檔、同一組欄位，但摘要與讀檔各自重新開檔。
10. **版本相容／遷移**：`SAVE_VERSION = 1` 從未升過，只在版本較新時警告。相容靠「讀檔後補救」：`_migrate_legacy_dabao_flags`、書眠等級補救、澄心落筆獎勵補發、舊水道搜刮補發——都依內容判斷，不依版本號。缺欄位一律用 `.get(..., 預設)`，新增欄位本身安全。

**現有三份存檔（唯讀）**：version 1，19~20 個欄位，`thumb_path` 存 `user://` 路徑字串。存檔格式是 Godot 二進位 `store_var`，不是 JSON，無法手動查看或修補。

## 4. 可沿用部分
- 原子寫入（先寫 tmp 再改名）＋一代 `.bak` 備份。
- `load_from_slot` 的整套還原順序（載入鎖、轉場鎖、出口防重觸發、讀檔後補救），已經過實戰。
- `SystemMenuControl` 的開關、暫停與縮圖快取。
- 縮圖機制（只要 UI 能讀 PNG）。
- `get_slot_summary` 的回傳格式可當摘要基礎。

## 5. 需要改造部分（影響範圍）

| 問題 | 影響 |
|---|---|
| 三格硬編碼（4 處） | 擴到 99 格：改 `SLOT_COUNT`，且 UI 必須改成動態產生；`_valid_slot` 與路徑 `%02d` 不需改 |
| 存讀共用一個畫面且綁在系統選單分頁 | 主選單無法直接叫出；還依賴 `get_tree().paused` 與 `SystemMenu` autoload |
| 主選單讀檔 | `load_from_slot` 假設 `/root/GameRoot` 已存在。主選單沒有 GameRoot，會落到「分支 3」（`change_scene_to_file(scene_path)`），跳過 `change_map_to` 與位置還原，多半無法正確進遊戲。需先建立 GameRoot 再呼叫（GameRoot 現已預設不播開場，這條路是安全的） |
| 99 格每次整份解析 | 分頁顯示時需分頁載入，或另存摘要 |
| 新增摘要欄位 | 不必改存檔格式：直接寫進同一字典，舊檔缺欄位用預設值；需決定舊檔無章節時 UI 顯示什麼（例如退回 `chapter_title`）。若要做獨立摘要檔才需新增檔案格式與重建機制 |
| 縮圖 | 只在系統選單開啟時快取，從別處存檔會用舊圖或無圖；縮圖是獨立 PNG，不會隨檔案刪除而清理 |
| 章節資料來源 | 需在 `MAIN_QUEST_DEFS` 新增章節編號，摘要才有可靠來源 |

## 6. 風險
- **舊存檔**：現有三份必須維持可讀；新增欄位一律給預設值；不要改名或搬動既有欄位。
- **場景切換**：讀檔是協程，`is_loading`、`map_transition_locked` 若中途失敗可能卡住（例如檔案損壞時中途出錯不會呼叫 `end_load`）。
- **覆蓋與誤讀**：目前沒有任何確認，也沒有「未儲存會遺失」提示；壞檔被當空格而可被覆寫。
- **狀態殘留**：讀檔只重置 GlobalState、任務、隊伍、背包；對話、戰鬥返回旗標、BGM 等暫態沒有統一重置（遊戲內讀檔是現況，主選單讀檔時問題較小）。
- **格式**：二進位 `store_var`，不能手動檢視或修補。
