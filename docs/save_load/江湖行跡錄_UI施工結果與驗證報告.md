## 三、相容性

- **原有三份正式存檔：保留且未動。** 所有測試都在隔離資料夾 `user://test_save_99/`、`user://test_chronicle/`（正式存檔的**副本**）進行；測試前後對 `user://save/` 九個檔案（`.save`、`.bak`、縮圖）做 MD5 比對，**完全一致**。
- **新欄位**：`chapter_number` 只是存檔字典新增的一個鍵；舊檔缺少它時，摘要用該存檔的主線 id（`main_001`）查正式主線定義還原，查不到才顯示「章節未記錄」。讀取不會因此失敗。`SAVE_VERSION` 仍為 1。
- **縮圖**：舊存檔的 140px 縮圖維持原樣、仍可顯示；只有「下次覆蓋該格」才換成 270px 新縮圖。
- **存檔路徑與編號規則**未變（`slot_%02d`），99 格不需要改路徑。
- **主選單讀檔**：已驗證能還原地圖、玩家位置、主線進度、旗標、隊伍（見驗證 #12），走的是**同一個** `load_from_slot`，沒有另寫第二套還原。**尚待老闆實機確認**完整遊玩感受（音樂、劇情狀態等）。

### 章節對應（請老闆確認）
目前主線資料只有一個定義：

| 主線 id | 中文章名 | stage 範圍 | 本次設定的 `chapter_number` |
|---|---|---|---|
| `main_001` | 靜默的琴聲 | 1～11（玉衡鎮調查 → 舊水道 → 夜談 → 準備前往烈風寨） | **1（第一章）** |

這是依「一份主線定義＝一章」的既有結構設定，**請老闆確認**：① `main_001` 是否就是第一章；② 序章與第一章是否要分開（現有資料**無法**可靠區分，我沒有自行拆分）；③ 烈風寨章開始後的章節編號等未來主線定義加入時再填。

## 六、待老闆驗收（請實機操作）
1. 遊戲內 ESC → 系統 → 儲存進度／讀取進度：入口、翻頁、點欄位、覆蓋確認、讀取確認、返回。
2. 主選單 → 讀取遊戲：讀存檔 01、02、03，確認進入遊戲後地圖／位置／隊伍／任務／音樂正常，且**不會**播開場。
3. 實際存一格新檔（例如 05、99），再讀回；看右側縮圖是否清晰（新存檔 270px）。
4. 舊三份存檔外觀與資訊是否顯示正確（章節應顯示「第一章」）。
5. 滑鼠點擊、Hover、鍵盤 ESC 的手感。
6. 確認上面的「章節對應」。
